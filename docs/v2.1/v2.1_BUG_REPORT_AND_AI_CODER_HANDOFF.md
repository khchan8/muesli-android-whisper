# Muesli for Android v2.1 — Bug Root-Cause Investigation & AI Coder Handoff Spec (`v2/v2.1`)

## 1. Issue #1: App Shutdown / Crash When Launching CAM++ Diarization After Recording
- **Root Cause A (`processWithCallback` JNI Crash in `SpeakerDiarizer.kt`)**: Calling `diarizer.processWithCallback(samples16kMono)` throws an uncaught `java.lang.UnsatisfiedLinkError` (which subclasses `java.lang.Error`, bypassing `catch (e: Exception)`) or triggers a native `SIGABRT` from an unattached C++ worker thread in `libsherpa-onnx-jni.so`.
  - **Fix in v2.1**: Replace `diarizer.processWithCallback(...)` with synchronous `diarizer.process(samples16kMono)` and change all native JNI `try/catch` blocks in `SpeakerDiarizer.kt` and `MeetingRecorderService.kt` from `catch (e: Exception)` to `catch (t: Throwable)`.
- **Root Cause B (Concurrent Native Heap Exhaustion)**: `MeetingRecorderService.kt` kept the heavy ASR model (`SherpaRecognizerHolder`) loaded in RAM while `SpeakerDiarizer.kt` simultaneously instantiated both `OfflineSpeakerDiarization` (which loads its own internal CAM++ copy) and a second `SpeakerEmbeddingExtractor` copy.
  - **Fix in v2.1**: Call `SherpaRecognizerHolder.release()` in `MeetingRecorderService.kt` immediately after `decodeWorkerJob?.join()` before starting diarization, and run `OfflineSpeakerDiarization` -> `diarizer.release()` sequentially BEFORE instantiating `SpeakerEmbeddingExtractor`.
- **Root Cause C (Unverified Model Path -> Native `ptr == 0L` Crash)**: Passing an unverified path to `OfflineSpeakerDiarization` when `3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx` or `sherpa-onnx-pyannote-segmentation-3-0/model.int8.onnx` is missing or stored under a different asset path (`model.onnx`) causes `require(ptr != 0L)` to abort.
  - **Fix in v2.1**: Implement `resolveVerifiedModelFile(...)` with recursive `assets/` and `files/` scanning, returning `null` and falling back to single-speaker timestamped segments if the ONNX file is missing.

## 2. Issue #2: Missing Audio Profile Configuration & Voice Enrollment UI
- **Root Cause**: v2.0 only allowed post-meeting speaker badge renaming inside `MeetingDetailScreen.kt` and lacked a dedicated screen to pre-enroll speakers before a meeting.
- **Fix in v2.1**: Add `SpeakerProfilesScreen.kt` (`package com.phequals7.muesli.ui`) + `SpeakerDiarizer.enrollSpeakerFromAudioSamples(...)` and `identifySpeakerFromAudioSamples(...)` so users can record a 6–8s voice clip per speaker (in English, Thai, or Chinese), test voice matching live with cosine similarity percentages, and manage profiles from Settings or `MeetingDetailScreen` ("Audio Profiles" top-bar button).
